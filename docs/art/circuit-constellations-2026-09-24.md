# 코어 서킷 별자리 — 형태 · 그림 작업 지시 · 2026-09-24

작성: Claude (main) · **받는 쪽: ChatGPT** · 사용자 지시 — "그림을 생성하는 것은 ChatGPT 한테 맡기자. 모든 다른 별자리 형태와 별자리 그림을 가지라고 해줘.
그래봤자 88가지 정도뿐이 안 되긴 하지만 최대한 다르게 그려 달라고 하자."

관련 — 규칙 · 값 `js/circuit.js` · `data/circuit.js` · 결정 기록 `CONTRACT.md` '코어 서킷 시안 2 — 별자리' ·
시안 페이지 `docs/balance/core-circuit-draft-2026-09-23.html`(브라우저로 열면 76기를 직접 찍어 볼 수 있다).

## 0. 한 줄

**뽑기 기체 76기 모두가 서로 다른 별자리를 갖게 해 달라 — 별의 자리(형태)와 그 뒤에 깔릴 별자리 그림(figure) 둘 다.**

지금 시안 페이지의 별자리는 Claude 가 코드로 만든 **자리 표시**다 — 모든 기체가 '아래 가운데에서 네 갈래가 부채꼴로 뻗는' 같은 뼈대에
각도만 몇 도씩 흔든 것이라 사실상 한 모양이다. 이것을 기체마다 다른 그림으로 바꾸는 일이다.

## 1. 바꾸지 않는 것 — 규칙이다

별의 **개수 · 이어짐 · 갈래 배정**은 전투 값과 묶여 있어 그림 쪽에서 바꿀 수 없다.

| 항목 | 고정값 |
|---|---|
| 점 | 기체마다 **37** — 코어 1 + 갈래 4 × (작은 별 8 + 전문 별 1) |
| 이어짐 | 갈래마다 **코어 → 1 → 2 → … → 8 → 전문 별(★)** 한 줄. 갈래 사이를 잇는 선은 없다 |
| 찍는 순서 | 안쪽(1)부터 바깥(8)으로. 그래서 1 이 코어에 가깝고 ★ 이 가장 끝이어야 읽힌다 |
| 갈래 이름 | A · B · C · D 가 무슨 갈래인지는 아래 §6 표 그대로(`js/circuit.js themesOf`). **A 가 그 기체에게 가장 어울리는 갈래**다 |
| 전문 별 | 갈래 끝 ★ — 지금은 잠겨 있다. 그림에서도 끝에 있어야 한다 |

## 2. 다르게 — 이것이 이번 일의 전부다

- **76기 모두 서로 다른 형태.** 좌우를 뒤집거나 돌리거나 크기만 바꾼 것은 **같은 형태로 본다**
- **실제 별자리(88개)를 참고해도 된다** — 사용자 말대로 본뜨면 88가지가 한계지만 76기는 그 안에 든다.
  단 **한 별자리는 한 기체에만** 쓰고, 그대로 베끼지 말고 그 기체의 모양 · 성격에 맞게 고친다. 어느 별자리를 참고했는지 `ref` 에 적는다
- **맞는 별자리가 없으면 기체 실루엣에서 새로 만든다** — 날개 · 포신 · 팔 · 다리 · 꼬리처럼 멀리 뻗은 부위를 따라 갈래를 놓으면 그 기체만의 모양이 된다.
  (Claude 는 '몸통 중심을 코어로, 가장 멀리 뻗은 끝 네 곳을 갈래 끝으로' 를 제안했었다 — 쓰든 말든 자유)
- **A 갈래는 그 기체의 가장 두드러진 부위에** — A 가 가장 그 기체다운 갈래라서, 그림에서도 가장 눈에 띄는 줄기가 되면 좋다
- 다르게 만들 손잡이 — 코어의 위치(가운데 · 위 · 한쪽) · 전체 윤곽(세로로 긴 · 가로로 넓은 · 사선 · 소용돌이 · 고리) ·
  갈래의 굽음(곧게 · 크게 휘게 · 지그재그) · 별 간격(촘촘 · 성김) · 대칭과 비대칭 · 갈래끼리의 길이 차
- 한 화면에 여러 기체를 나란히 놓았을 때(도감 · 격납고) **한눈에 구별돼야 한다** — 이게 합격 기준이다

## 3. 규격

### 3-1. 형태(좌표) — `data/circuit_layout.js`

```js
/* 코어 서킷 별자리 좌표 — ChatGPT. 좌표계 520 × 430(시안 페이지와 같다), 왼쪽 위가 0,0 */
export const CIRCUIT_LAYOUT = {
  ignis: {
    ref: 'Aquila',                          // 참고한 실제 별자리(없으면 null)
    core: [260, 215],
    A: [[x, y] /* 1 … 8 */, [x, y] /* ★ */],   // 9 점
    B: [/* 9 점 */], C: [/* 9 점 */], D: [/* 9 점 */],
    art: 'assets/circuit/ignis.webp',
  },
  /* … 76기 */
};
```

| 검사 | 기준 |
|---|---|
| 점 수 | 기체마다 코어 1 + 갈래마다 9 = 37 |
| 판 안 | 모든 점이 가장자리에서 **24 이상** 안쪽 |
| 별 간격 | 어느 두 점이든 **22 이상** 떨어진다(휴대폰 320px 에서도 손가락으로 고를 수 있게) |
| 선이 안 겹친다 | 한 갈래의 선이 다른 갈래의 선과 **교차하지 않는다**. 같은 갈래 안에서도 스스로 꼬이지 않는다 |
| 이름 자리 | 각 ★ 바깥쪽에 갈래 이름이 들어갈 **90 × 20** 빈 칸이 판 안에 있다 |
| 안에서 밖으로 | 갈래의 1 → 8 → ★ 가 대체로 코어에서 멀어진다(찍는 순서가 눈으로 읽혀야 한다) |
| 서로 다름 | 두 기체의 형태를 크기 · 위치 · 회전 · 좌우 뒤집기로 맞춰 봐도 같지 않다 |

### 3-2. 그림 — `assets/circuit/<id>.webp`

- **1040 × 860**(좌표계의 2배), 투명 배경. 좌표 × 2 자리가 그림에서 의도한 별의 자리와 맞아야 한다
- 내용은 **별자리 그림(figure) 만** — 옛 성도(星圖)처럼 별들을 잇는 형상 그림. 기체의 모습이나 성격이 보이게
- **별 · 선 · 글자 · 숫자는 그리지 않는다** — 코드가 좌표로 그린다(찍음 · 찍을 수 있음 · 잠김 상태가 바뀌어야 해서). 한글 · 영문도 굽지 않는다
- 판 바탕이 남색 흑철(`#0b1118` ~ `#131d28`)이다. 그림은 그 위에 **낮은 대비**로 얹혀 별이 먼저 읽혀야 한다 — 청록 · 은빛 계열 가는 선, 밝은 면 금지
- 계획서(`docs/balance/mech-traits-plan-2026-09-22.md`) §7 아트 방향 그대로 — 긁힌 금속 · 은은한 청록 광원 · 전문 별 쪽만 절제된 황동.
  무지개 네온 · 무작위 마법 문양 · 렌즈 플레어 금지
- **기체 그림과 같은 세계에서 온 것처럼** — 기체 그림은 손으로 그린 것이다. 코드로 찍은 도형처럼 보이면 반려된다(사용자가 전에 한 번 반려했다)
- 생성 프롬프트 · 파일명 · 크기 · 해시는 지금까지처럼 `docs/art/` 에 기록한다

## 4. 순서

1. **파일럿 6기 먼저** — IGNIS · DUNE · MULE · BASTION · PATCH · SOLARIS(시안 페이지 첫 화면 · 등급 고르게). 사용자가 보고 방향을 정한다
2. 나머지 70기
3. 스토리 기체 4종(ROOK-3 · ROOK-3 MOD · ROOK-3 RE · VALKEN-4)은 얻는 길이 아직 없어 이번 범위 밖이다

## 5. 경계

- **main 에서 한다** — `assets/circuit/` · `data/circuit_layout.js` · `docs/art/`. 화면 동결 파일(`index.html` · `style.css` · `themes/` · `js/game.js`)은 건드리지 않는다
- `data/circuit.js` · `js/circuit.js` 는 Claude 몫이다(값 · 규칙). 갈래 배정이 그림과 안 맞아 바꾸고 싶으면 `CONTRACT.md` 에 적어 달라 — Claude 가 값을 다시 재서 바꾼다
- **받으면 Claude 가 할 것** — 시안 페이지가 `CIRCUIT_LAYOUT` 과 그림을 읽게 바꾸고, §3-1 검사를 도구로 만든다(점 수 · 판 안 · 간격 · 교차 · 이름 자리 · 서로 다름)
