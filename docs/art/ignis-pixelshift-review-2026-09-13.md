# Ignis 36프레임 정수 이동 검토본 · 2026-09-13

사용자가 기존 관절 36프레임의 중간 프레임이 깨져 보인다고 보고했고,
움직임 참고 GIF를 다시 제공했다. 운영은 승인된 10프레임으로 복구했다.
**이 문서의 새 36프레임은 검토용이며 게임에 연결하거나 운영에 배포하지 않았다.**

## 수정

기존의 핀 가중치 회전·픽셀 재샘플링을 없앴다. 원본 날개와 종아리 조각을 통째로
정수 좌표 0–2px 옮기며 몸통·머리·팔·무기와 관절 덮개는 원본 위치에 둔다.
날개는 바깥쪽, 다리는 안쪽으로 최대 2px, 위로는 최대 1px 움직인다.
전체 부유는 최대 10px이며 승인된 강화 발광을 유지했다.

참고 GIF의 3초 주기·작은 상승/하강·금빛 발광·미세한 날개/다리 움직임을 참고했다.
GIF 자체의 갑옷 재해석·윤곽 흐려짐·좌우 흔들림은 따르지 않았다.
앞으로 지킬 원본·투명도·정렬·검수 기준은 [제작 기준](ignis-animation-rules.md)에 정리했다.

첫 정수 이동 후보를 검수하다 오른쪽 긴 날개 `(406,271)` 부근의 검은 외곽선 일부가
고정층에 남는 것을 발견했다. 날개 분리 범위를 외곽선 전체까지 넓혀 이중 테두리를 수정했다.
원본 외곽 이동으로 비워진 지점과 관절 내부 구멍을 구분해 확대 확인했으며,
검사에서 제외한 외곽 지점도 위치·알파·이동 방향을 기록했다.

## 파일

- 검토본: [ignis-idle-36f-pixelshift.webp](review/ignis-idle-36f-pixelshift.webp)
- 440×420, 36프레임, 3초, 실제 투명 알파, 무손실 WebP, **5,993,328 bytes**.
- SHA-256: `7a13d9a30f77800a0fa15f56f37f399c6542d1d32a14e6d97523780752749aac`.
- 수치/검증: [JSON](review/ignis-idle-36f-pixelshift.json).
- 재현: `python tools/build_ignis_idle_pixelshift.py`. Python 3와 Pillow가 필요하다.
  기본 출력은 `dist/art-review/ignis-idle-36-pixelshift/`이며 원본 파일을 덮어쓰지 않는다.
- `--source`, `--out`으로 경로를 지정할 수 있다. 도구가 개별 PNG 36개,
  투명 6×6 시트, 전 프레임 검수 패널, 마스크·메타데이터도 생성한다.
- 회사에서 이어볼 수 있도록 WebP와 생성기를 저장했다. `docs/art/review/`는
  운영 빌드의 복사 대상이 아니며 `js/sprites.js`는 10프레임만 참조한다.

## 검수 범위와 한계

- 출력의 불투명 픽셀마다 원본 좌표와 부품 이동량을 추적했다. 새 그림/보간 픽셀 0.
- 고정 외장 60,871픽셀·관절 보호층 5,078픽셀, 관절 내부 검사 5,041픽셀 확인.
- 모든 프레임의 고정 비발광 픽셀 차이 0, 검사한 관절 내부 구멍 0.
- 모든 36 PNG와 디코딩한 WebP 사이 표시 RGBA/알파 차이 0, 원본 PNG 해시 유지.
- 36장 모두 독립적인 전체 캔버스 교체 프레임으로 기록했다. 첫 프레임의 자동
  투명 여백 자르기를 같은 무손실 VP8L 픽셀로 다시 포장한 뒤 다시 디코딩 검증했다.
- 부품 위치 상태는 4개다. 각 상태와 전환을 포함한 36장 전체의 어깨·무릎·발끝을
  확대 비교했다. 시작→끝 위치 차이는 0, 마지막→처음의 최대 채널 차이는 2다.
- 원본 조각이 관절 보호층 뒤로 가려지거나 드러나므로 전체 불투명 픽셀 수가 원본과
  매 프레임 같다는 뜻은 아니다. 고정·이동 픽셀 검증과 시각적 평가는 구분한다.
- 로컬 비교 화면에서 PNG 36장 로드, 한 프레임 이동, 밝은/어두운 배경,
  최종 WebP의 440×420 브라우저 표시를 확인했다. 비교용 HTTP 서버/브라우저 연결에
  일시적 로딩 실패가 있어 미리보기에 재시도를 넣었다. 실제 게임 적용 검수는 하지 않았다.
- 기존 WebP의 부분 프레임 압축은 별도 재합성 검사에서 오류가 재현되지 않았다.
  압축 형식이 원인이었다고 단정하지 않는다. 이전 검수는 움직이는 부위의 시간축 품질을
  충분히 확인하지 못했으며, 이번 후보도 사용자에게 보이는 완성도 평가와 별개로 기록한다.
