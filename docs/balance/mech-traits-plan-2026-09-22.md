# 기체별 선택 특성 — 코어 서킷 계획

## 1. 요청과 제안의 구분

사용자 요청: 기체별로 선택하는 특성 5~6개, +0.1~+5.0 수준의 성장,
패스 오브 엑자일의 트리 또는 와우의 차크람을 연상시키는 아름다운 형태.

이번 기본안은 **기체마다 6노드 · 3갈래 · 각 갈래 2단계인 원형 코어 서킷**이다.
포인트·해금 레벨·효과 상한·상호 배타 규칙은 아래의 **검증 전 제안값**이다.
사용자가 이 세부 수치까지 확정한 것으로 취급하지 않는다.

- '차크람'은 현재 요청의 특정 와우 화면을 식별하지 못했으므로 **고리·방사형 구도**로 해석한다.
  다른 화면을 뜻했다면 참고 이미지 확인 후 외형만 조정한다. 게임 규칙까지 추정하지 않는다.
- POE의 연결 노드·선택 경로라는 시각 언어를 참고하되, 거대한 트리나 자산을 복제하지 않는다.
- 사각 카드 여섯 개를 단순히 원으로 늘어놓는 안은 채택하지 않는다.
  중심 기체 문장, 금속 링, 각인, 독립 일러스트 아이콘과 에너지 연결선을 함께 설계한다.
- 기존 기체 고유 스킬·특화기술, 파츠·인챈트, 스킬 강화는 유지한다.
  선택 특성은 기존 개성을 보완하는 작은 조정층이다. 첫 버전에 새 행동·타격 수·무한 회복을 추가하지 않는다.

## 2. 기체 범위와 소유 단위

현재 `ROBOT_TYPES`는 **47종: 기존 30 + 세트 03의 13 + 스토리 기체 4**다.
예전 30종만 대상으로 삼지 않는다. 몬스터와 보스는 제외한다.

- 정의는 기체 type별 6개, 배분·프리셋은 소유 기체 uid별로 저장한다.
- 동일한 type을 여러 대 소유할 수 있는 경로가 생겨도 서로의 배분을 공유하지 않는다.
- 등급이 높다고 포인트·노드 수·성장 상한을 더 주지 않는다.
- 스토리 변형 `rook3` / `rook3_mod` / `rook3_re`는 서로 다른 정의다.
  변형 시 배분을 어떻게 이전할지는 실제 획득·변환 경로 조사 후 확정한다.
  호환되지 않는 노드를 억지로 옮기지 않고 포인트를 반환하는 것이 기본안이다.
- 기존 저장본의 특성 없음은 유효한 0배분이다. 기체나 계정 저장본을 초기화하지 않는다.

## 3. 선택과 성장 규칙 — 제안

| 항목 | 기본안 |
|---|---|
| 선택지 | 6개. 내측 기초 A1/B1/C1, 외측 전문 A2/B2/C2 |
| 시작점 | 중앙 기체 코어, 무료·효과 없음·6개 수에 포함하지 않음 |
| 실제 연결 | 코어→A1→A2 / 코어→B1→B2 / 코어→C1→C2 |
| 선행 조건 | 해당 기초 특성 3랭크 이상이면 같은 갈래 전문 특성 투자 가능 |
| 전문 선택 | 외측 전문은 동시에 1개 갈래만 활성화. 기초 3개는 자유 배분 |
| 랭크 | 각 노드 0~10, 1포인트로 1랭크 |

| 해금 시 | Lv.10에서 누적 5포인트, Lv.60에서 30포인트. 과거 레벨도 동일하게 계산 |

| 저장 | 먼저 임시 배분 → 수치 비교 → 적용. 클릭 즉시 서버 저장 금지 |
| 프리셋 | 기체당 최대 3개 제안. 활성 프리셋 하나만 전투에 반영 |

예: 전문형은 A1 10 + A2 10 + B1 10, 분산형은 A1/B1/C1 각각 10.
전문 선택 없이도 유효한 빌드다. 전문 갈래를 바꾸면 기존 전문 투자분을 반환한
미리보기를 먼저 보여준다. 기초를 3 미만으로 내릴 때 연결된 전문 투자도 반환한다.
한 번의 확인으로 전체 유효 배분을 적용하며 몰래 포인트를 버리지 않는다.

전문 특성은 새로운 큰 패시브를 공짜로 얹는 노드가 아니다.
같은 +0.1~+5.0 범위에서 평타/스킬/특정 상황 중 어디를 강화할지 선택하는 노드다.
기초 노드만 찍은 분산형도 경쟁력이 있도록 비교한다.

## 4. +0.1~+5.0의 단위와 계산

**+5.0을 모든 능력치에 같은 정수로 더하지 않는다.** 내구 5와 치명 확률 5는 가치가 다르다.
기본 해석은 '노드의 누적 효과가 소수점 한 자리로 +0.1~+5.0 범위에 표시된다'다.
50번 누르는 +0.1 반복 강화 대신 10랭크와 세 종류의 증가폭을 사용한다.

| 효과 종류 | 랭크당 제안 | 10랭크 | 표시/적용 |
|---|---:|---:|---|
| 내구·공격·방어 | +0.5 | +5.0 | % 상대 증가 |
| 평타·스킬 피해 보정 | +0.5 | +5.0 | % 상대 증가, 지정한 피해 경로에 한 번만 |
| 속도 | +0.2 | +2.0 | % 상대 증가, 턴 수 민감도 검사 필수 |
| 치명·회피 확률 | +0.1 | +1.0 | %p 절대 증가, 기존 상한 유지 |
| 기존 관통·흡혈 계수 | +0.1 | +1.0 | %p. 기존 효과가 있는 기체만, 상한·차단 유지 |
| 기존 방벽·수리량 | +0.2 | +2.0 | % 상대 증가, 기존 감쇠·회복 상한 유지 |
| 조건부 피해 보정 | +0.5 | +5.0 | % 상대 증가, 조건 불충족 시 0 |

- 예: 공격력 200에 +5.0%는 210. 치명 10.0%에 +1.0%p는 11.0%다.
- 정의에는 `unit: percent | percentagePoint`를 명시한다. UI에 단위 없는 '+1.0' 금지.
- 저장하는 값은 정수 랭크다. 보너스는 0.1단위 정수(tenths)로 합산 후 비율로 변환한다.
  +0.1%와 +0.1%p 모두 내부 비율 0.001이지만 **곱셈/덧셈 대상이 다르다**.
- 동일 채널 보너스는 합산한다. 공격 +5% 두 개는 +10%이지 1.05²가 아니다.
- 기체/레벨/파츠/세트 등 기존 정적 계산을 `S0`라고 할 때 일반 상대 보너스는
  `S0 × (1 + Σbonus / 100)`, 확률 보너스는 `S0 + Σbonus / 100`을 사용한다.
  구체 삽입 위치는 `computeStats`의 현재 계산 순서를 조사하고 테스트로 고정한다.
- 피로도·지형·전술·흘려내기와의 기존 순서를 보존하며, 특성 합산 뒤 기존 상한을 다시 보장한다.
  효과를 얻은 결과에 다시 특성을 곱하지 않는다. 화면 미리보기와 서버가 동일한 함수를 쓴다.
- 항상 치명 스킬에 치명 확률을 찍어도 추가 이득이 없음을 안내한다.
  흡혈 차단·치명 무효·필중·방벽/수리 감쇠를 특성으로 우회하지 않는다.
- 같은 빌드에서 공격 증가와 스킬 피해 증가가 겹치는 효과는 전체 출력으로 재서 제한한다.
  '노드당 최대 5%'만으로 전체 빌드가 안전하다고 판정하지 않는다.
- 조건부 특성은 난수 호출을 추가하지 않는 것부터 만든다. 조건·발동 시점·적용 대상을 명시한다.

사용자가 의도한 수치가 %가 아니라 **고정 능력치 +0.1~+5.0**이라면 이 절을 먼저 바꾼다.
여기 적힌 초안으로 실제 밸런스 파일을 바로 수정하지 않는다.

파쇄 방어 하한 완화, 수리 감쇠 제거, 확률로 무한 발동하는 자원 회수.
파쇄·교란·표적은 강력한 기존 효과이므로 수치 보강을 확정하기 전에 엔진 의미와 상한을 확인한다.
지원 불가/효과 없는 조합은 배포 전 다른 유효한 갈래로 교체한다.

## 7. 시각 디자인 — 원형 코어 서킷

### 주안과 비교안

- **A 원형 차크람(우선)**: 중앙 기체 엠블럼, 120도 간격의 세 갈래, 갈래마다 내측·외측 노드.
  동심 금속 링과 각인으로 하나의 기계 장치처럼 만든다. 실제 연결선은 세 갈래만 표시한다.
  장식 링은 가늘고 끊어진 비발광선으로 두어 이동 가능한 경로로 오인하지 않게 한다.
- **B 축소 별자리 트리(비교 시안)**: 같은 6노드·동일한 규칙을 비대칭 가지 구도로 배치한다.
  기능을 바꾸지 않고 구도만 비교한다. 거대한 줌/드래그 탐색은 6노드에 불필요하므로 넣지 않는다.
- 두 시안을 같은 IGNIS·같은 배분·같은 PC/모바일 크기로 만들어 비교한다.
  먼저 사용자가 외형을 선택한 후 아이콘 전량 생산과 게임 UI 구현으로 간다.

### 아트 방향

남색 흑철·긁힌 금속·은은한 청록 광원, 전문 노드에는 절제된 황동/금색 테두리.
기존 격납고·캡슐의 기계식 디자인과 통일한다. 무지개 네온·무작위 마법 문양·과한 렌즈 플레어 금지.
기체별 문양/색상은 달라도 선택/잠금/오류 색의 의미는 고정한다.

| 구성 | 제작 및 규격안 |
|---|---|
| 중앙 코어 | 기존 기체 이미지의 읽기 쉬운 크롭 + 기체 ID 문장. 정적 이미지 사용 |
| 링·선·랭크 눈금 | SVG 벡터. 작은 화면에서도 선명하며 실제 데이터로 그린다 |
| 특성 아이콘 | 그림 기반 256×256 투명 원화 → 128×128 웹 자산. 44/56px에서 실루엣 확인 |
| 아이콘 내용 | 용접 장갑·냉각 핀·조준 렌즈·분리 탄두·수리 드론 등 효과를 설명하는 물체 |
| 배경 | 문자 없는 저대비 정비 회로판, 선택 노드 뒤에는 밝은 디테일 금지 |
| 텍스트 | HTML로 표시. 생성 이미지에 이름·숫자·랭크·한글을 굽지 않는다 |

초기 파일럿 36노드의 아이콘 명세부터 작성한다. 동일 효과는 공용 그림 재사용 가능하지만
한 기체 안의 서로 다른 효과를 색깔만 다른 같은 그림으로 때우지 않는다.
282개 모두 독립 원화를 만드는 것을 전제하지 않는다. 공용 모티프와 기체 고유 전문 아이콘을 구분한다.
최종 파일명·해시·생성 프롬프트·투명 경계·사용 위치를 manifest로 관리한다.

### 화면과 조작 명세

- PC: 왼쪽 기체 목록, 중앙 링, 오른쪽 선택 특성 설명·현재→예상값, 하단 남은 포인트/초기화/적용.
- 모바일 360/375/390px: 기체 선택 → 링 → 선택 노드 상세 → 적용 바.
  선 위에 긴 한글을 얹지 않는다. 링 옆 번호와 하단 목록의 이름을 연결한다.
- 모바일 링 기준 320px: 중심 (160,160), 내측 반지름 65px, 외측 128px,
  각도 −90/30/150도. 터치 영역 최소 44px, 아이콘 36~44px. 가장자리와 노드 간 간격 검수.
- 선은 노드 뒤 레이어, 장식은 pointer-events 없음. 인터랙션은 실제 버튼으로 구현한다.
- 선택/미선택/선행 미충족/다른 전문 선택으로 잠김/최대 랭크/미저장 변경을 구분한다.
  색 외에도 자물쇠·체크·10/10·점선과 텍스트를 사용한다.
- 키보드 탐색은 A1→A2→B1→B2→C1→C2. 포커스 표시와 노드별 이름·랭크·잠금 사유 제공.
- '1 올리기/1 내리기/최대/반환' 버튼과 취소 제공. 30포인트를 30번만 눌러야 하는 UI 금지.
- 노드 선택은 효과 설명만, 배분과 서버 적용은 별도. 다른 기체/화면으로 이동 시 미저장 경고.
- 연결 발광 180~240ms, 상시 회전 없음. reduced-motion에서 이동·펄스 제거.
- 모바일 상세/적용 바가 노드나 브라우저 안전 영역을 덮지 않게 한다. 가로 스크롤 0.
- 대전 상대/자신의 정보에서 활성 전문 특성과 실제 효과를 볼 수 있게 설계한다.

### 시각 합격 기준

PC 1440×900, 모바일 360×800·390×844에서 같은 품질로 읽혀야 한다.
축소 화면에서 기체·세 갈래·선택 경로를 3초 안에 구분하는 사용자 검수 실시.
본문 대비 4.5:1, 큰 텍스트·주요 경계 3:1 이상 목표. 200% 확대에서 기능 접근 가능.
원화 파일 존재만으로 완료 처리하지 않는다. 실제 화면의 선택·잠금·만렙·편집 상태를 캡처해 검수한다.

## 8. 구현 경계와 데이터 계약 — 아직 미구현

현재 `CONST.TRAIT`는 **합동전 보스 특성**이다. 여기에 플레이어 특성을 섞지 않는다.
별도 `MECH_TALENTS` 정의와 `talentBuild` 저장 필드를 제안한다.

- 정의: 기체 type → 6노드 `{id, branch, tier, requires, maxRank, effect, unit, stepTenths, icon}`.
- 저장: 소유 기체 uid → `{version, revision, activePreset, presets:[{id,name,ranks}]}`.
  보너스·사용 가능 포인트·계산된 스탯은 클라이언트 저장값을 신뢰하지 않는다.
- 순수 모듈 제안: `validateTalentBuild`, `talentBudget`, `resolveTalentEffects`.
  서버와 클라이언트가 같은 정의/계산을 사용한다. 스키마/API의 최종 경로는 구현 시 CONTRACT에 확정한다.
- 변경 요청에는 기체 uid, 배분 정수, expectedRevision, 중복 요청 키를 포함하는 안.
  서버가 소유권·포인트·선행·전문 배타·전투 중 변경 금지·정의 버전을 검증한 뒤 원자적으로 저장한다.
  모르는 노드·타 기체 노드·음수·소수 랭크·NaN·초과 랭크는 거절한다.
- 전투 진입 시 배분 버전과 파생값을 스냅샷에 고정한다. 진행 중 전투에는 새 배분이 소급되지 않는다.
  아레나 방어 등록·점령 수비·레이드·합동전·프리셋 복원·재접속 모두 감사한다.
- 일반 상태 동기화로 특성 필드를 덮어쓸 수 없게 한다. 서버 전용 적용 경로를 둔다.
- 빈 구형 저장은 0배분으로 읽는다. 스키마 번호는 구현 직전 최신 번호 다음을 예약한다.
  계획 단계에서 현재 21 다음 번호를 선점하지 않는다.
- 정의/효과 버전을 balanceVersion에 포함하고 아레나 스냅샷 재계산을 검증한다.
  스냅샷 복원 함수가 새 필드를 빠뜨려 특성을 없애지 않게 한다.
- 전투력 산정은 단순 가산 상수가 아니라 실제 승률/출력과 비교해 보정한다.
  사람이 특성으로 강해졌는데 매칭 전투력은 그대로인 상태로 배포하지 않는다.

## 9. 검증과 밸런스 승인

현재 BASTION Lv.60 경계 이탈 및 파츠 다양성 확장 검사 문제는 특성과 별도로 남아 있다.
이번 특성을 넣어 그 문제를 덮거나 기존 테스트 실패를 새 정상으로 바꾸지 않는다.

1. **현행 기준선 저장**: 최신 흘려내기·특화기술·합동전 규칙에서 전투 길이/무승부/승률을 측정한다.
2. **0배분 회귀**: 모든 모드에서 기존 입력·시드의 승패와 사건 순서가 동일해야 한다.
3. **정적 전수 검사**: 47종×6노드, ID 중복·효과 호환·선행 DAG·단위·아이콘 누락 검사.
   가능한 랭크 배분은 수학적으로 검증하며 모든 배분마다 전투 전수 시뮬을 하지는 않는다.
4. **조합 샘플링**: 전문 3종·기초 분산·경계 배분·합법 무작위 배분을 Lv.10/30/60,
   맨몸/대표 파츠/끝판 장비에서 측정. 대칭 선후공·공통 시드·95% 신뢰구간을 기록한다.
5. **초기 목표(제안)**: 같은 기체·레벨·장비·30포인트의 대표 빌드 평균 승률은 대체로 40~60%.
   특정 상대 상성은 허용하되 모든 모드/상대에서 한 갈래가 우세하면 재설계한다.
   30포인트 대 0포인트 거울은 55~65%를 첫 목표로 삼고 넘으면 누적 효과를 줄인다.
   민감 후보는 선후공 합계 10,000판 이상 재측정한다. 수치는 측정 후 확정한다.
6. **민감 효과**: 속도 턴 경계·저치명/저회피 기체·다단 타격·치명 무효·흡혈 차단·수리/방벽 장기전.
   상한 도달 시 UI가 실제로 오르지 않는 효과를 증가한 것처럼 표시하지 않아야 한다.
7. **기존 검사**: terrcheck / arenacheck / battlecheck / specialcheck / jointcheck /
   raidcheck / frontcheck / bandcheck / insightcheck / skill / 관련 파츠·저장 검사.
   경제 시뮬은 특성을 반영하도록 먼저 고친 뒤 새 수입·진행 곡선을 측정한다.
8. **새 검사**: talentcheck(검증·단위·계산), talentdb(동시성·이관·중복 요청),
   talentbalance(배분별 측정), talent-ui-check(반응형·잠금·미리보기·적용·프리셋).

수치 변화가 작아도 효용을 설명할 수 있어야 한다. 설명 불가능한 +0.1을 채우기용으로 넣지 않는다.
실측 전에는 '밸런스가 맞는다' 또는 '282개 완성'이라고 기록하지 않는다.
