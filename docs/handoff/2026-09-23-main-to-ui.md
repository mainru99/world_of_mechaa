## 2. 새 필드 두 개 — `ROBOT_TYPES[]`

### `curve` (선택) — 성장 2차 항
`computeStats`(`js/stats.js`) 가 `base + grow×(lv-1) + curve×(lv-1)²/(MAXLV-1)` 로 계산한다. Lv.MAXLV 값은 `grow + curve` 만큼 오른 값.
음수 = **조숙형**(중반에 세고 만렙에 평범) · 양수 = **대기만성**. 지금 ZEPHYR · POLARIS · AQUILA · GOLIATH CIEL(조숙) · LONGBOW · VESPER · QUASAR · GOLIATH RUST(대기만성).
- **화면이 알아 둘 것** — `js/game.js` 의 `STAT_MAX` 는 `base + grow×(MAXLV-1)` 로 스탯 바 상한을 잡는다. 곡선 기체는 이보다 최대 약 3% 높다.
  여유 35% 안이라 지금은 넘치지 않지만, 새 화면에서 다시 짤 때는 `computeStats({type, level: MAXLV, …})` 로 잡는 편이 정확하다
- 격납고 · 도감에 '조숙형 / 대기만성' 딱지를 붙이고 싶으면 `curve.hp < 0` / `> 0` 으로 가린다

### `family` (선택) — 아종 집안
`'nimbus'` · `'goliath'` · `'hydra'`. 같은 차체의 형제다 — 속도 · 치명 · 회피 · 구간이 같고 무장 · 스킬 · 성장 모양이 다르다.
- 표준형(아래 등급에서 계보가 이어지는 기체) — `nimbus_c` · `goliath_s` · `hydra_s`. 나머지는 같은 등급 안에서 **분화**로 열린다(`data/lineage.js` 의 `LINEAGE_SIBS`)
- 도감 · 뽑기 목록에서 형제를 묶어 보여 줄 때 쓴다

## 3. 숙련 = 특성 포인트 — `traitPoints(level)`

사용자 결정(2026-09-23): **숙련은 그 기체의 특성 포인트만 준다.** 5레벨마다 1 · 10레벨마다 1 더 · 최고 레벨에 2 더.

| 레벨 | 1 | 5 | 10 | 20 | 30 | 59 | 60 |
|---|---|---|---|---|---|---|---|
| 포인트 | 0 | 1 | 3 | 6 | 9 | 16 | 20 |

- `js/stats.js` 의 `traitPoints(level)` · 수치는 `CONST.MASTERY`. **레벨에서 바로 나오므로 저장하지 않는다**(DB · API 변경 없음)
- 코어 서킷 계획(`docs/balance/mech-traits-plan-2026-09-22.md`) 3절의 `min(30, floor(level / 2))` 를 **이것으로 바꾼다**
- **특성 수 · 비용을 포인트 총량에 맞춰 제한하지 않는다**(사용자 지시). 모든 노드를 다 찍을 수 있게 짜면 누구나 같은 빌드가 된다.
  특성은 넉넉히 두고, 플레이어가 **필요한 것을 골라** 찍는 구조가 재미의 핵심이다
- 다음 기체는 숙련으로 얻지 않는다 — **조각**(뽑기 · 상점 · 대전 등, 출처는 설계 예정)으로 모은다

## 4. 개발 계보 — `js/lineage.js` · `data/lineage.js`

계보는 **조각이 차도 조립해도 되는가**를 가르는 문이다. 사용자 결정:
- C 는 뿌리 — 언제나 조립
- **합류**(앞 기체가 여럿) — 앞 기체를 **모두** 가져야 조립
- **갈림**(다음 기체가 여럿) — 플레이어가 하나를 고른다(개발 목표 — 조각 출처 설계와 함께 붙는다)
- **분화** — 아종은 표준형을 가지면 조립
- **뽑기 입구** — 약한 연결을 끊은 자리. `orbit`(R) · `swift`(UC) 는 **조각으로 조립 못 하고 뽑기로만** 얻는다. `lens` 는 다음 기체가 없다
- 이미 가진 기체의 조각은 막지 않는다(중복 보상)

API(DOM 없음 · 서버와 화면이 같이 import):

```js
canDevelop(type, ownedTypes)  // → { ok, why, need }  why: owned | root | sibling | parents | gacha | story | unknown · need: 모자란 기체 type[]
developable(ownedTypes)       // → 지금 새로 조립할 수 있는 type[] (갈림길 '개발 목표' 후보)
lineageView(ownedTypes)       // → { [type]: { state: 'owned'|'open'|'locked'|'gacha', need, parents, children, std, sibs } }
parentsOf(type) · childrenOf(type) · siblingStd(type) · siblingsOf(type) · isRoot(type) · isGachaEntry(type)
```

- 데이터 — `LINEAGE`(연결 81 · `[앞, 뒤, 잇는 이유]`) · `LINEAGE_SIBS`(분화 5). 시안 — `docs/balance/lineage-draft-2026-09-23.html`(기체를 누르면 앞뒤 계보 · 이유)
- **상점 조립(`POST /api/shop {action:'assemble'}`)에 계보 문이 달렸지만 꺼져 있다** — `CONST.LINEAGE.gate = false`.
  켜면 막힌 조립은 `{ ok:false, error:'lineage locked', why, need }` 로 온다. **계보도 화면이 나온 뒤 사용자 지시로 켠다**
- 필요한 화면 — ① 계보도(상태 네 가지로 칠하기 · 갈림 '택1' · 합류 '모두 N' · 뽑기 입구 표시) ② 보관함 조각 카드에 '조립 가능 / 앞 기체 필요(이름)'
- 검사 — `node tools/lineagecheck.mjs`

## 6. 전투력 보정 배수 — `pwK`

전투력(`powerOf`)이 스탯만 봐서 AURIC(EP 1위로 표시, 실제로는 EP 끼리 가장 약함) · QUAKE(지원형이 부풂) 같은 어긋남이 있었다.
기체마다 **실제 등급 안 승률**에 맞춘 배수를 둔다 — `data/powercal.js`(`tools/powercal.mjs --write` 가 만든다), 범위 ×0.86 ~ ×1.17.
- `computeStats` 결과에 `pwK` 가 붙을 수 있고 `powerOf` 만 그것을 곱한다. **전투는 한 판도 바뀌지 않는다**(sim.js 는 pwK 를 읽지 않는다)
- 표시 · 매칭(±15%) · 아레나 방어 기록에 들어간다
- **화면이 알아 둘 것** — 전투력은 `powerOf` / `power` 결과만 쓰면 된다. 스탯 표에 `pwK` 를 띄우지 않는다. 스탯으로 전투력을 따로 계산하지 않는다
