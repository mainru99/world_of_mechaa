## 0. 가장 먼저 — 대전이 **교대 전투**가 됐다 (운영에서 켜져 있다)

**지금 UI 브랜치의 대전 화면이 예전처럼 1:1 로 재생하면 화면의 승패와 서버의 승패가 어긋난다.** 새 대전 화면을 짤 때 아래를 반드시 넣는다.

- **규칙** — 대전(아레나 정상 · 비상 출격 · 지목 친선전)에서 **양쪽이 모두 두 기**면 앞 기체가 쓰러지는 즉시 둘째가 나온다. 한쪽이 한 기면 예전처럼 1:1.
  토벌 · 점령 · 전선 · 레이드 · 시련 · 조각 작전은 그대로다. 스위치 `CONST.RELAY.on`(지금 `true`)
- **재생 — 서버 응답만으로 이렇게 부른다**(`js/sim.js` · 응답은 `/api/battle/start`)
  ```js
  const P = makeUnit(r.nameP, myType, r.statP, r.tacticP);
  const E = makeUnit(r.opponent.callsign, r.opponent.type, r.statE, r.tacticE);
  const rl = r.relay;                       // 교대가 없으면 null
  const events = rl
    ? simulate(P, E, r.seed, { P: [makeUnit(rl.nameP2, rl.typeP2, rl.statP2, rl.tacticP2)],
                               E: [makeUnit(rl.nameE2, rl.typeE2, rl.statE2, rl.tacticE2)] })
    : simulate(P, E, r.seed);
  ```
- **새 사건 `{ t:'swap', side:'P'|'E', i, name, type, hp, maxhp }`** — 그 쪽의 **기체 그림 · 이름 · 체력 막대**를 바꾸고 SP 를 0 으로.
  ⚠ 체력 막대의 최대치는 **이 사건의 `maxhp`** 를 쓴다. `P.maxhp` 는 전투가 끝난 뒤 값이라 교대 뒤에는 틀린다.
  '건너뛰기' 로 처음부터 다시 그릴 때는 첫 기체 상태로 되돌린 뒤 다시 그린다
- **결과 창** — 경험치는 **나온 기체끼리 나눈다**(첫째 60% · 둘째 40% · 둘째가 안 나왔으면 첫째 100%). 피로도는 나온 기체마다 한 판치.
  `r.reward`(첫째) + `r.relay.robot2` = `{ uid, level, exp, fat, fatAt, lv:{amt,from,to}, fatGain:{add,now} }`(둘째가 나왔을 때만). 둘째 기체 행도 로컬 상태에 받아 적는다(uid 로 찾기)
- **상대 카드** — `/api/battle/find` 의 `opponent.bench = [{ type, level, name }]` — 상대의 둘째를 미리 보여 줄 수 있다
- **전술 둘** — 요청 `/api/battle/start { tactic, tactic2 }`. `tactic2` 가 없으면 첫째와 같다. 둘째 전술 고르는 칸을 둘지는 UI 판단
- **참고 구현** — main 의 `js/game.js`(동결 예외로 최소 수정) — `ROWAR.startBattle` 재생부 · `applyServerBattle` · `playBattle` 의 `cu` · `mx()` · `swapIn()`. 아래 8절 표
- 알아 둘 것 — 한 판이 대략 **두 배 길다**. 재생 속도 · 건너뛰기를 쓰기 쉽게 둘 것

## 2. 코어 서킷 화면 — 새로 만들 것 (격납고 안)

서버 · 규칙 · 전투 반영까지 끝났고 **화면만 없다.** 기체마다 별자리 하나.

- **판** — 갈래 4개(A ~ D) × 작은 별 8개 + 갈래 끝 **전문 별 ★** 하나 = 36. 갈래 종류는 14종 중 그 기체에 맞는 4종(`themesOf(type)` · 이름 `CIRCUIT_THEMES[t].ko`)
- **포인트** — `traitPoints(level)`(Lv.60 에 20). 별 하나 = 포인트 1. **갈래 안에서 안쪽부터**(A3 은 A2 가 있어야)
- **전문 별 ★** — 그 갈래 **1 ~ 8 을 다 찍은 뒤 포인트 1 로 찍는다**(사용자 결정 — 공짜로 열리지 않는다). 20점이면 ★ 는 최대 둘(8★+8★+2)
- **별 목록 · 효과** — `constellation(type)` → `[{ id:'A1'…'A*', br, i, theme, kind:'a'|'b'|'x'|'c', fx:{효과:값}, notable?, text? }]`.
  `kind` 는 모양 — a 무난(올리기만) · x 곁들임(둘을 반씩) · b 뾰족(+2 −1) · c 가장 뾰족(+3 −2). 바깥으로 갈수록 뾰족하다.
  효과 이름 — 내구 hp · 공격 atk · 방어 def · 속도 spd · 치명 crit · 회피 eva · 스킬 피해 skill · 관통 확률 pen · **턴마다 회복 regen** · 가속(공격마다) accel.
  crit · eva · pen 은 %p(더하기), 나머지는 %(곱하기), regen 은 '최대 내구의 %/턴'. ★ 는 `text`(예 '회피한 직후 반격 사격')
- **찍기 판정** — 화면이 미리 `blockOf(type, taken, id, points)` 로 이유 문장을 보여 준다(서버와 같은 함수). 합은 `circuitFx(type, taken)` · ★ 효과는 `circuitNotables`
- **API** — `POST /api/circuit`
  - `{ action:'take', uid, stars:['A1','A2',…] }` → `{ uid, type, level, points, taken, left, open:['A*',…], resetCost, rcores }` · 위반은 `bad stars { why }`
  - `{ action:'reset', uid }` → 위와 같은 모양 + `spent`. **비우기는 처음부터 정제 코어 1개**(사용자 결정). 빈 서킷은 `nothing to reset` · 모자라면 `not enough rcores`
  - **비우기 단추를 누르면 주의 문구만 띄우고**(사용자 결정) 확인하면 보낸다 — 문구는 `circuitResetWarn()` 을 그대로
- **별자리 그림 · 좌표**
  - 그림 `assets/circuit/<기체 id>.webp` 76장 — 1040 × 860, 청록 은빛 선화, 알파 투명. 사용자가 그려 온 것이다
  - 좌표 `data/circuit_layout.js` — `CIRCUIT_LAYOUT[id] = { core:[x,y], A:[[x,y]×9], B, C, D, art, … }`(좌표계 **520 × 430** — 그림은 2배라 그대로 겹치면 된다. 9번째 점이 ★),
    이름 칸 `CIRCUIT_LABEL_BOXES[id] = { A:[x,y,90,20], … }`. 선은 코어 → 1 → … → 8 → ★ 로 그린다. **사용자가 13기를 손으로 옮겼다(`hand:true`) — 좌표를 고치지 말 것**
  - 76기 모두 검사 통과(`node tools/circuitlayoutcheck.mjs`)
- **아트 방향**(시안에서 사용자가 받은 것) — 판은 어두운 남색 흑철 · 찍은 별 청록 광원 · ★ 황동(찍으면 채워지고 빛남 · 못 찍으면 점선). 기체 그림 위에 별자리를 얹는다
- **참고 화면** — 시안 페이지 `docs/balance/core-circuit-draft-2026-09-23.html`(찍기 · 빼기 · ★ · 프리셋 · 능력치 표가 전부 돈다). 로직을 그대로 옮겨도 된다
- 서킷 효과는 **전투에 들어간다** — 찍으면 격납고 스탯 · 전투력이 바로 바뀌어야 한다(1절 `computeStats`)

## 3. 정제 코어 — 재화 · 합치기 · 정제 코어 뽑기

- **재화** — `/api/state` 의 `rcores`(**state 밖**에 있다). 지갑에 코어 옆 칸
- **합치기** — `POST /api/refine { n }` → `{ made, spent, cores, rcores, rev }`. 코어 10개 → 정제 1개(`CONST.REFINE.need`). 지금은 **합치기 말고 얻을 길이 없다**
- **정제 코어 뽑기** — 뽑기 화면에 **세 번째 창구**. `POST /api/pull { count, cur:'rcore' }` · 1회 = 정제 1(`PULL_CUR.rcore.cost`).
  확률 미리보기는 `PULL_TABLE_RC` · `ROBOT_RARITY_RC`(기체 15% · 유니크+에픽 14.5%). 코어 10개 값에 확률만 소폭 높은 것은 **기획 의도**(사용자 확인)
- 뽑기 화면(UI 브랜치 `js/ui/recruitment.js`)에 창구를 더할 때 **스토리 기체 거르기**(앞 문서 0절)도 같이

## 4. 조각 회수 작전 — 하루 두 번 (새 화면)

- **규칙** — 하루 2번(UTC 하루 = 한국 09:00 에 바뀐다). 난이도 셋 **정찰 · 회수 · 강습** — 내 기체와 **같은 레벨** 몬스터 · 체력 · 공격 ×0.7 / ×1.0 / ×1.3.
  이기면 조각 1 / 2 / 3, 지면 횟수만 쓴다. **C ~ R 기체 조각만**(사용자 결정) — 개발 목표가 C ~ R 이면 목표로, 아니면 열 수 있는 C ~ R 중 가장 높은 등급으로
- **API** — `GET /api/salvage` → `{ day, endsAt, daily, left, tiers:[{tier, ko, shard, type, level, mul}], goal:{type, have, need} }`(`goal` 이 **작전 조각이 갈 기체** — 개발 목표와 다를 수 있으니 따로 적을 것)
  · `POST /api/salvage { tier, uid? }`(uid 없으면 고른 기체) → `{ win, got, tier, foe:{…, stats}, seed, robot, parts, stats, left, goal }` · `no tries left { endsAt }` · `no goal`
- **재생** — `runSalvage(stats, foe, seed)`(`js/salvage.js`) 가 사건을 준다. 시련과 같은 방식
- `/api/state` 의 `salvage: { left, daily }` 로 지휘소 · 메뉴에 '오늘 2 / 2' 를 띄울 수 있다

## 5. 조각 합성 — 보관함 안 (새 화면)

- **규칙** — 같은 등급 조각 **6 ~ 10개**(기체 섞어도 됨) + 스크랩. 6개 25% → 하나마다 +7% → 10개 53% 로 **한 등급 위**, 1% 로 **명작(두 등급 위)**, 나머지는 동급.
  수량은 넣은 수에 비례(동급 ½ · 성공 ⅓ · 명작 ⅕). **결과 기체는 개발 목표 우선** — 결과 등급이 목표 등급과 같으면 목표, 아니면 그 등급 무작위. 에픽은 못 넣는다
- **미리보기** — `synthCheck(mats, items)`(`js/shardsynth.js`) → `{ rar, n, cost, rates:{up, master, same} }` 또는 `{ error }`(문장 그대로 보여 준다). 서버와 같은 함수
- **API** — `POST /api/shop { action:'synth', mats:{ 기체 id: 개수 } }` → 상점 보기와 같은 모양 + `synth:{ grade:'same'|'up'|'master', rarity, type, qty, goal, from, used, spent, rates }`
- '명작' 은 연출 한 번 줄 만하다(1%)

## 12. 서버가 느리다 — 알고 있을 것

한국 접속이 `*.workers.dev` 에서 **LAX** 로 들어가고 DB 는 **APAC** 라 요청마다 0.5 ~ 1초 · 조회가 많은 요청은 몇 초였다. main 이 **스마트 배치**를 켰다(적용 중).
화면은 **요청이 느릴 수 있다고 보고** 짠다 — 누르면 바로 눌린 표시(로딩) · 두 번 누르기 막기 · 결과를 기다리는 동안 재생 준비. 서버는 두 번 눌러도 한 번만 처리한다(선점 · 낙관적 잠금)
