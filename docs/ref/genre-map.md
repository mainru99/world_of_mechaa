# 장르 지도 — ROWAR 에 무엇이 붙고 무엇이 안 붙나 (2026-09-17)

사용자가 장르 목록 250여 개를 참고용으로 남겼다. **그대로 옮겨 적는 것은 값이 없다.**
우리 구조에 대 보고 **붙는 것 · 값이 드는 것 · 안 되는 것**으로 갈라 적는다.

---

## 0. 가르는 기준 하나

ROWAR 의 엔진은 **씨앗 하나로 결정되는 1:1 자동 전투**(`js/sim.js`)와,
그것을 여러 겹으로 이어 붙이는 **돌파**(`js/breach.js`) 두 개뿐이다.

> **전투를 감싸는 장르는 싸다. 전투가 무엇인지를 바꾸는 장르는 비싸다.**

이 한 줄이 아래 표 전부를 설명한다.
그리고 값을 정하는 두 번째 축이 있다 — **D1 무료 한도는 '읽은 행' 기준**이다.
플레이어 동작 하나가 행을 여럿 읽으면 그 장르는 수치와 무관하게 못 쓴다.

---

## 1. 우리는 이미 이것들이다

새로 만들 것이 아니라 **이미 가진 것**이다. 여기에 이름을 붙여 두면
"또 만들자" 는 판단을 막을 수 있다.

| 장르 | 우리 쪽 | 상태 |
|---|---|---|
| 오토배틀러 / 오토체스 | `sim.js` 전체 | 코어 |
| 캐릭터 수집 게임 | 기체 30종 · 뽑기 | 있음 |
| 키우기 / 육성 | 레벨 · 파츠 · 강화 · 스킬 강화 | 있음 |
| 루트 기반 RPG (루터) | 파츠 파밍 · 인챈트 · 세트 | 있음 |
| **비동기 멀티플레이** | 아레나 — 스냅샷끼리 붙는다 | 있음 |
| Persistent World | 점령전 — 접속 안 해도 칸이 회복된다 | 있음 |
| 방치형 / Idle | 원정(시간이 지나면 받는다) | 얕게 |

## 2. 붙이면 싸게 붙는 것 — 전투를 안 바꾼다

### ★ 로그라이트 / 덱빌딩 로그라이크 — **가장 값이 크다**

`runBreach` 를 그대로 쓰고 **한 판(run)** 을 얹는다. 겹을 계속 잇고, 사이사이
고르게 한다. 새 전투 코드가 **0줄**이다.

왜 이게 1순위인가 — `BALANCE.md` ⓔ 가 적어 둔 미해결 하나가
**"끝판에 계속 굴릴 이유가 없다"** 였다. 파밍은 천장에 닿으면 멈춘다.
로그라이트는 **천장이 없는 대신 매번 처음부터**라 그 구멍에 정확히 맞는다.

- **Drafting** — 겹을 깰 때마다 파츠/축복 3개 중 1개(목록의 *Drafting Game*)
- **Inventory Management Puzzle** — 가져갈 수 있는 칸이 제한된다
- 저장은 진행 중 run 하나. `player` 에 컬럼 하나면 된다(전선 `campaign` 과 같은 수법)

### ○ Ghost Racing — 주간 시련에 바로 붙는다

시련은 **이미 결정적**이다(주 번호에서 시드가 나온다). 그래서 남의 판을
**그대로 재생할 수 있다** — 같은 시드, 같은 함수. 순위표 옆에 '1위의 판 보기' 를
붙이는 데 새 계산이 없다. 읽는 행도 그 사람의 스냅샷 하나뿐이다.

### ○ Idle Management — 원정을 깊게

지금 원정은 '보내고 기다린다' 하나다. 목록의 *방치형 · Idle RPG · Idle Management* 는
**접속 안 한 동안 무엇이 쌓이는가**를 설계로 본다. 우리는 이미 서버 시각으로
정산하므로(피로도 · 점령 회복) 얹을 자리가 있다.

### ○ Asynchronous Multiplayer 를 더 — 협동 PvE

레이드가 이미 "서버 전체가 하나의 막대를 깎는" 구조다. 같은 수법으로
**같이 미는 전선**(길드 없이, 전 서버가 한 칸을 민다)이 가능하다. 행 읽기는 집계 한 줄.

### △ Deduction / Optimization Puzzle — 파츠가 이미 퍼즐이다

조합의 수가 이 게임의 존재 이유였다(`BALANCE.md` ⓔ). 목록의 *Optimization Puzzle*
("가능한 해답보다 더 효율적인 해답") 이 정확히 그것이다. **모드를 만들 것이 아니라
지금 있는 것을 그렇게 보이게** 하면 된다 — 조합을 견주는 화면, 기록.

## 3. 값이 드는 것 — 할 수는 있으나 대가가 분명하다

| 장르 | 무엇이 드나 |
|---|---|
| SRPG / 전술 (진형 · 지형 위 위치) | `sim.js` 가 1:1 고정이다. **장르를 바꾸는 일**이다(`DESIGN.md` F장 §7) |
| 카드 배틀 / CCG | 전투 판정을 통째로 새로 만든다. 오토배틀러를 버리는 선택 |
| 몬스터 수집 RPG | 몬스터를 소유 대상으로 올리는 것은 **금지**다(`AGENTS.md`) |
| 도시 건설 · 공장 자동화 | 격자·배치 UI 가 통째로 새로 든다. 그림도 전부 새로 |
| 연애 / 육성 연애 | 캐릭터 초상화와 분기 대사가 **그림과 글의 총량**으로 든다 |
| 메트로배니아 · 플랫포머 · 액션 | 실시간 입력. 우리 전투는 **녹화 재생**이라 아예 다른 축이다 |

---

## 4. 안 되는 것 — 구조가 막는다

**실시간 동시 접속이 필요한 전부.** MOBA · 배틀로얄 · FPS/TPS · 히어로 슈터 ·
전술 FPS · 아레나 슈터 · 소셜 디덕션 · 카우치 코옵 · MMO.

이유는 취향이 아니라 배관이다.
- WebSocket 상시 연결이 없다. Worker 는 요청마다 깨어나고 끝난다
- **D1 무료 한도가 '읽은 행' 기준**이라, 초당 몇 번씩 상태를 주고받는 순간 예산이 없다
- 우리 전투는 **서버가 결정하고 클라가 재생**한다. 실시간은 그 전제를 깬다

**프레임 단위 입력이 필요한 전부.** 리듬 · 탄막 · 런앤건 · 레이싱 · 격투.
전투가 이벤트 배열의 재생이라 입력이 끼어들 자리가 없다.

---

## 5. 그래서 무엇을 할 것인가 — 지금은 **아무것도 안 붙이는 것**이 답이다

모드가 이미 아홉이다(뽑기 · 대전 · 파견 · 원정 · 점령 · 시련 · 레이드 · 합성 · 전선).
그런데 **Lv.4 를 넘긴 계정이 3개다**(운영 32계정 실측, `DESIGN.md` F장 §0).

깔때기 맨 위가 66% 에서 새는데 아래를 넓히는 일을 반복하면, 잘 만든 모드가
아무도 못 보는 곳에 쌓인다. **열 번째 모드보다 전선 1장이 먼저 굴러가야 한다.**

> 이 문서의 쓸모는 '무엇을 만들까' 가 아니라 **'만들자는 생각이 들 때 값을 먼저 보는 것'** 이다.
> 로그라이트는 그 순서가 왔을 때 1순위다 — 새 전투 코드가 0줄이고,
> 이미 적어 둔 미해결(끝판에 할 일)에 정확히 맞는다.
