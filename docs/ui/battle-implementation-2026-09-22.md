브랜치: `codex/ui-rebuild`. ChatGPT 메인 / Claude 서브. 기준 커밋 `57deeaa` 이후 작업이며 main의 파일·커밋을 반입하지 않았다. 서버, DB, 전투 계산, 밸런스, 기체 에셋 변경 없음. 운영 배포 없음.

## 시안과 실제 기능의 대응

- 기준: 사용자 `rowar_ui_rebuild/fight.png`의 PC 왼쪽 모드 메뉴, 파란 아군/붉은 적군, 중앙 VS, 부대 카드, 전투력 비교, 전장 안내와 빨간 출격 버튼. 모바일은 모드 탭→양쪽 기체→전력→전술→출격 순서.
- 현재 실제 모드는 일반 대전 / 친선 대전 / 연습 대전. 일반 매칭은 플레이어·훈련 기체·몬스터를 포함하므로 시안의 '랭크 대전'이라는 이름을 그대로 쓰지 않았다.
- 시안의 5:5 편성, 가상의 계급·경험치 막대·보상 범위는 표시하지 않는다. 현재 출격 선봉 1기를 사용하며 실제 계산 스탯/전투력, 계정명, 전적을 표시한다. 레이팅의 기본값 1000을 실제 조회값처럼 표시하지 않는다.
- 기체 그림은 기존 정지 PNG. 격납고 전용 이그니스 WebP는 대전 준비·전투·결과 어디에도 사용하지 않는다. 이그니스 레인 스킬 재생은 유지.
- 전술을 출격 버튼보다 먼저 배치한다. 스킬/장비 상세 비교는 '기체 분석' 펼침 영역에 유지한다. 상대 회피·방어·전투력에 따른 기존 안내도 보존.
- 실제 비용, 무료 친선/연습, 비상 출격(크레딧 보상만), 토벌 구간·주간 한도, 보상 결과 로직을 유지한다.

## 2:1 범위 — 완료와 미완료를 구분할 것

`battleView`는 `allies[]`, `enemies[]`를 입력받는다. 아군 2기와 보스 1기를 배치하고 각 진영의 실제 전투력을 합산하는 **준비 화면 표시 구조**를 구현했다. PC는 아군 두 카드를 나란히, 모바일은 아군 두 카드를 세로로 두고 보스 카드를 맞은편에 길게 표시한다.

현재 게임의 어댑터는 선봉 1기를 전달한다. UI 브랜치의 기존 레이드 순차 전투를 동시 2:1로 바꾸지 않았다. main의 합동전 엔진 반입·새 API·동시 3기 재생 HUD는 미구현이다. 사용자 브랜치 분리 지시에 따라 이후 통합 결정 때 별도 작업해야 한다. 현재 2:1 실전이 된다고 보고하면 안 된다.

## 비동기와 재시도 계약

- `_battleRequest`는 내비게이션, 모드 변경, 연습 상대 생성, 로그인 때 증가한다. 일반/친선/토벌 검색 응답은 요청 번호·현재 화면·계정 ID·S 객체가 일치할 때만 표시한다.
- `_battleFindOpts`에 마지막 검색 문맥을 보존한다. 만료 후 재검색과 다음 상대 없는 '한 판 더'에서도 친선 target/pick 또는 토벌 tier를 유지한다. 로그인 시 초기화.
- `battleRetry`는 준비 중인 상대의 duel/hunt 문맥으로 다시 찾는다. 연습은 새 로컬 가상 상대를 만든다.
- `startBattle`의 응답이 도착하기 전에 다른 화면으로 이동하면, 같은 계정/상태일 때 확정 보상만 반영하고 현재 화면을 다시 그린다. 재생을 떠나도 동일하다. 이전 계정 응답은 새 계정에 적용하지 않는다.
- 서버 보상은 클라이언트에서 계산하지 않는다. `applyServerBattle`은 정상 결과나 이탈 결과에서 한 번만 호출된다. 재생 중 다른 소비 동작은 기존 공통 guard가 차단한다.
- `.tacbtn[data-k]`만 전술 선택 대상으로 갱신한다. 친선 상대 기체 선택의 강조 표시를 지우지 않는다. `aria-pressed`도 함께 갱신.

## 재개 방법과 다음 순서

이 UI 작업 폴더에서 `node tools/ui-preview.mjs 8810` 실행. `http://127.0.0.1:8810/`에서 시작하기→대전→연습 대전으로 실제 로컬 재생을 확인한다. `http://127.0.0.1:8810/__battle-layout`은 2:1 표시 예시 전용이다.

다음 UI 단계는 **파견**: `detachment.png`와 `renderHunt`/`renderExped`를 대응한다. 현재 1기 원정, 토벌의 출격비·등급·주간 한도를 유지한다. 동시 2기 토벌/레이드는 main과 통합 결정 없이 임의 반입하지 않는다. 이후 랭킹/도감, 로그인, 나머지 모달·상점·시련·전선의 일관성 정리와 통합 검수가 남아 있다.

현재 구현 체크포인트는 UI 브랜치에만 커밋·푸시한다. 정확한 해시는 `git log -1 --oneline`과 같은 이름의 원격 브랜치로 확인한다. 운영 main 병합·배포는 하지 않는다.
