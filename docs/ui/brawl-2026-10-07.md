## 상태와 범위

Claude 인계 기준 `4494895` (운영 기록 `95b7fc3d`, schema25). ①~④ 위에 ⑤ 화면을 로컬 구현했다. **⑥ 시범 운영, 원격 푸시 및 실제 배포는 미실시.** `CONST.BRAWL.on=false` 유지. 사용자가 기존 ROWAR를 이어 하도록 요청했으며 서버·밸런스 재설계나 미래 MMORPG 계획은 이번 범위가 아니다.

## 연결된 흐름

1. 스위치가 켜진 경우 대전의 난투 버튼 → 서버 로비 GET. 운영 off면 메뉴를 노출하지 않고 직접 열어도 준비 중을 표시한다.
2. 오늘 대여 6기 중 남은 티켓 수까지 선택, 보유 UC 이상을 합쳐 6종까지 선택. C는 자동 포함. 시작 때만 티켓을 소비한다.
3. 상점 5칸 구매/새로고침/다음 라운드 잠금. 서버 확정 골드만 표시한다. 같은 기체 3기 자동 합성은 공용 규칙을 따른다.
4. 기체 선택 → 목표 자리 선택으로 전위2/후위2/대기6 이동·교체. 판매·런 마감은 별도 확인 버튼을 누른다. 클릭과 Enter 모두 지원한다.
5. 시너지 활성 효과·참여 기체, 등급별 등장 몫, 수입 예상과 실제 수입 차이, 패배 시 잃을 목숨, 보상/연습 런 구분을 표시한다.
6. 서버의 4대4 events를 재생한다. 빈칸이 있어도 자리 ID 유지. 내구·SP·방벽·회복·치명·회피·흘려내기·과열·격파와 기록 표시. 1/2/4배, 건너뛰기, 같은 확정 기록 다시 보기.
7. 라운드 결과 또는 최종 승수·목숨·기록, 서버 지급 보상(크레딧/스크랩/정제 코어/목표 조각)을 표시한다. 지갑은 GET으로 확인하며 지급 숫자를 로컬에서 더하지 않는다. 주간 순위에는 서버 기록만 표시한다.
8. 닫기·재접속 후 진행 중인 런 복구. 끝난 런의 전체 재생·개별 보상 응답은 서버가 영구 보관하지 않으므로 재접속 뒤 추측해 복원하지 않는다. 주간 기록·지갑으로 확인한다.

## 안전 처리

- 각 POST에 마지막 서버 run.rev. 계정 저장 `rowar.rev`와 별개이며 난투 응답으로 계정 revision을 올리지 않는다.
- UI pending 동안 중복 쓰기와 다른 재화 조작을 차단한다. 계정 객체/ID를 캡처하고 전송 층에서 토큰 변경까지 검사한다. 늦은 결과가 새 계정·닫힌 모달을 열지 않는다.
- timeout/409/결과 불명확은 POST를 반복하지 않고 GET으로 읽는다. GET도 실패하면 쓰기를 잠그고 새로고침을 요구한다. 확정되지 않은 전투를 임의로 재생하거나 보상을 만들어 표시하지 않는다.
- 지갑 GET 동안 로컬 지갑이 바뀌면 오래된 응답으로 덮지 않는다. 확인 실패 표시 및 재확인 버튼 제공.
- 기존 600ms 클릭 보호는 난투 진입/단계 전환에 유지하되 동일 화면의 선택·전투 tick마다 재무장하지 않는다. 기존 방식은 즉시 자리 이동과 빠른 재생의 Skip을 막았다. 단계 전환은 스크롤을 맨 위로, 같은 화면 갱신은 스크롤·포커스를 유지한다.
