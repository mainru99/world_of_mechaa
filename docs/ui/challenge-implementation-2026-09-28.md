# 주간 시련·공동 레이드 이관 · 2026-09-28

## 시안과 구현 범위

- `IMPLEMENTATION.md`, `rebuild-plan-2026-09-20.md`, 협업 계약 및 기존 시련/레이드 서버·공유 규칙을 확인했다. 전용 도전 시안은 없으므로 `fight.png`의 PC 모드 선택·큰 상대 장면, `detachment.png`의 출격 준비·현황 패널을 같은 화면 언어로 연결했다.
- PC는 좌측 작전 선택 → 상대/주간 종료 → 준비·기록·순위의 구도다. 900px 이하는 상단 두 모드, 600px 이하는 세로 패널/간결한 순위표다. 주요 행동·변경 경로는 44px 이상이다.
- 시련은 실제 주간 몬스터·지형, 서버 선택 규칙과 일치하는 출전 기체 1기, 최고 점수·순위·무료/무제한 조건을 표시한다. 지형 보정은 양쪽에 적용된다.
- 레이드는 실제 주간 보스, 선봉/예비 순차 1~2기, 공동 체력·한 판 체력의 차이, 하루 잔여 횟수·기여 순위를 표시한다. 동시 2:1 전투를 구현한 것은 아니다.
- 결과 화면은 서버 확정 점수·누적 피해·반영된 피해·보상·잔여 횟수와 복귀/격납고 경로를 정리했다. 모든 기체/몬스터는 기존 정지 PNG다. 새 그림·밸런스·API·DB 변경 없음.

- 조회 응답은 요청 순번·현재 화면·탭·계정 ID·상태 객체가 일치할 때만 적용한다. 캐시도 계정/상태 객체별이며 주간 종료 후 다시 조회한다. TTL은 기존 시련 30초/레이드 20초를 유지한다. 주기 폴링을 추가하지 않았다.
- POST 요청과 재생 중에는 같은 계정의 새 도전을 잠근다. 탭을 바꾸어도 중복 요청이 생기지 않는다. 실패하면 잠금을 해제하고 최신 기록 조회로 돌아간다. 자동 재전송하지 않는다.
- POST 성공 후 화면을 떠났어도 같은 계정의 레이드 지갑·캐시는 반영한다. 이전 화면의 재생은 새로 열지 않는다. 계정이 바뀌면 옛 응답을 적용하지 않는다.
- 재생 중 화면을 떠났다가 돌아와도 기존 요청 순번이 바뀌므로 옛 결과/다음 기체 재생이 새 화면을 덮지 않는다.
- 시련 POST에는 `endsAt`/`winBase`가 없으므로 공유 규칙의 `weekEnd(r.week)`/`TRIAL_WIN_BASE`로 캐시 표시 필드를 채운다. 점수와 승패는 응답값을 사용한다.
