처리 중 중복 저장/정제와 정제↔뽑기/상점 쓰기를 막는다. 실패 후 최신 기록을 조회하는 동안에도 잠금을 유지한다. 서버 응답 대상 UID는 요청 당시 것으로 고정하며 다른 기체를 살펴봐도 바뀌지 않는다. 다른 계정/게임 상태의 늦은 응답은 적용하지 않는다. 창을 닫았거나 이동한 뒤 같은 계정에 완료된 소비·저장은 보존하되 창을 강제로 다시 열지 않는다. 오류/연결 실패 때 재화를 추정 차감하지 않고 서버 기록을 다시 확인한다.

서버는 별 목록을 정규 순서로 돌려주고, 빈 서킷은 저장 기체에서 생략할 수 있다. UI는 `robot.circuit || []`로 취급한다. `net` 전송 함수는 새 계정에 이전 요청의 동기화 revision을 기록하지 않는다.

CSS 클래스 `cc-layout`, `cc-side`는 기존 도감의 `cv-layout`, `cv-side`와 분리했다. 모바일 기존 정보 탭이 감춰지는 설계에서도 새 서킷 진입이 보여야 한다. 지갑의 접근성 문구는 시각적으로 숨기고 스크린 리더에 제공한다.

## 운영 반영 전 필수 API 조율

`CONTRACT.md`의 Claude 담당 요청: `server/battle.js` find/next opponent가 플레이어의 `circuit` 또는 서버 확정 stats를 제공해야 한다. 현재 내부 판정에는 상대 서킷이 있지만 준비 응답에 빠져 있다. 프론트는 누락된 상대 능력치와 우세 판정을 **미확인**으로 표시한다. start 응답의 실제 서버 stats로 재생하므로 전투 판정은 맞는다. 이 표시 대체는 API 계약 완료가 아니며 운영 반영 전에 보완한다. 서버가 `opponent.circuit`를 주면 `setPending`이 보존할 준비를 했다. stats 방식을 택하면 UID별 전달과 카드 어댑터/회귀 검사도 연결한다.
