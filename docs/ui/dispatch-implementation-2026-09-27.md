# 파견 화면 이관 · 2026-09-27

## 범위와 실제 규칙

- 시안 `Downloads/rowar_ui_rebuild/detachment.png`의 PC 임무 표·좌측 분류·기체 준비·진행 현황, 모바일 임무/현황 탭을 구현했다.
- 이 브랜치의 서버가 제공하는 **원정 3종(기체 1기·동시 1건)**과 **즉시 토벌 6단계**만 표시한다. 시안의 여러 기체 파견, 임의 임무 보상, 동시 3건, 가속은 기능으로 만들지 않았다.
- 준비 기체는 정지 PNG다. 편성 중인 기체를 원정으로 보내면 편성에서 제외되고 다른 기체가 남아야 한다는 실제 규칙을 버튼/경고에 반영했다.
- 원정 보상 예상치는 `CONST.EXPED`와 출발 기체 레벨에서 계산한다. 실제 보상·귀환 가능 여부는 서버가 확정한다. 토벌에는 `CONST.HUNT`의 상대 레벨·출격비·스크랩 배수·코어/파츠 확률, 주간 한도를 사용한다.
- 진행 시간은 `/api/state`/출발 응답의 `endsAt`으로 1초마다 표시만 갱신한다. 출발·수령 중에는 중복 요청을 막고, 계정이 바뀐 뒤 돌아온 응답은 적용하지 않는다.

## 검수

- 로컬 예시 계정 `node tools/ui-preview.mjs 8811 --sample-dispatch`. PC 1265px에서 9개 임무/한 기 준비/진행 패널 표시, 선봉 IGNIS 선택→출발→편성 제외→귀환→보상 수령/지갑 갱신 확인. 샘플 보상 `+200 크레딧/+40 스크랩`은 생산 보상 값이 아니라 UI 시험 값이다.
- 모바일 390/360px에서 임무 목록·진행 현황 탭, 토벌 선택과 정지 선봉 그림 확인. 360px `documentElement.scrollWidth=360`, 페이지 가로 넘침 없음. 1024px에서도 가로 넘침 없음. 브라우저 도구 이미지로 시각 검수했으며 별도 PNG 파일은 저장하지 않았다.
- `tools/dispatch-ui-check.mjs`에서 9개 임무, 예상 보상, 주간 한도·크레딧 부족, 원정 시작/종료, 한 기 제한, 중복 출발/수령, 계정 전환 후 늦은 응답 격리, 보상 한 번 반영을 검사했다.
- 운영 API/계정에서 재화를 소비한 시험은 하지 않았다. 실제 서버 통합 검수는 UI 완성 후 병합 단계에 남는다.
