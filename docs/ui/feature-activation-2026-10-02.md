## 검사

- tools/feature-activation-check.mjs: 실제 SQLite+서버로 기존 장착 귀속/보관함 미귀속, 계정 원본·다른 기체 프리셋 보존/반복 이관, 귀속 장착 거절/재화 불변, 기체별 저장/최초 장착 귀속, 계보 거절 시 조각·재화 보존/가능 기체 조립을 검사한다. 실제 renderBag와 shopAssemble을 실행해 잠긴 버튼/가능 수/이유/계보 진입 및 요청 차단도 확인한다.
- bindcheck와 loadout-ui-check는 양 모드·해제·프리셋·합성을 실제 SQLite로 검증한다. 기존 계정 공용 presetcheck는 명시적 legacy 모드로 유지하고 구성값을 복원한다. shopcheck에는 선행 기체가 없을 때 거절/조각 불변 및 선행 보유 후 성공을 추가했다. 비활성 고정 UI 검사는 승인된 활성 정책을 검사하도록 갱신했다.
- 최종37종 순차 검사·npm run build·git diff --check 통과. 검사 과정에서 구형 공용/계보 비활성 전제에 따른 실패를 수정했으며 서버 규칙을 약화하지 않았다.

## 복구·남은 항목

문제가 확인되면 우선 활성 스위치와 이전 Worker/파일의 일치를 판단한다. 이전 Worker로 되돌리는 동안 귀속/기체 프리셋 열의 데이터는 보존하며 자동으로 지우지 않는다. 전체 DB Time Travel 복원은 활성화 이후의 다른 플레이 진행도 되돌리므로 일반적인 스위치 복구 대신 실행하지 않는다. 본 기록의 bookmark는 복구 판단용이며 실제 복원을 수행한 것은 아니다.

휴대폰 실기기 검수는 사용자 요청으로 생략. 계정 복구·사운드/음량·마켓 정책·저사양/장시간 및 신규 사용자 관찰은 별도 후속 범위다.
