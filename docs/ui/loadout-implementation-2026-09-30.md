장착 목록은 자유 파츠/지금 기체 전용을 먼저 표시한다. 다른 기체 전용은 설명을 흐리게 보여 주고 장착 대신 **귀속 풀기**를 제공한다. 처음 장착하면 귀속된다는 규칙은 목록에 짧게 표시하며 반복 확인 팝업을 만들지 않는다. 현재 장착한 전용 파츠도 슬롯 목록에서 귀속을 풀 수 있다. 해제해도 장착은 유지되고 다음 기체가 장착하면 다시 귀속된다.

프리셋은 격납고에서 보고 있는 기체의 장비 창 안에서 관리한다. 선봉/편성은 바꾸지 않는다. 각 칸의 이름·4슬롯·빈 칸·분해된 파츠·다른 기체 전용을 구분한다. 비워 둔 슬롯은 적용 시 해제하고, 없는/다른 기체 전용 슬롯은 **현재 장비를 유지**한다. 서버가 `bound`와 `missing`에 함께 실은 슬롯을 중복으로 “분해됨”이라고 설명하지 않는다. 활성 모드의 목록은 `bind.presets[robotUid]`, 비활성은 기존 `presets`를 사용한다. 삭제에도 항상 robotUid를 보내 활성 모드 계약을 충족한다.

합성에서는 서로 다른 기체 전용 재료의 추가 선택을 막고, 귀속 상속을 예고한다. 실제 POST는 서버가 판정한다. 성공 POST에 귀속 정보가 없으므로 활성 모드의 결과 표지는 GET으로 확인한다. 확인 실패 시 재료/보상/스크랩의 확정 결과는 먼저 보존하고 귀속 확인이 필요함을 알린다. 합성 중 닫거나 다른 창을 열면 결과 창으로 덮어쓰지 않는다.

## 상태·실패 처리

- 조회는 장비/프리셋/귀속 메타데이터와 조회 시 정산될 수 있는 숙련 items만 반영한다. 기체 레벨/EXP/피로·전적·편성·일반 재화·전투 상태는 되감지 않는다. parts/items/기체 레벨·슬롯 스냅샷이 조회 사이 바뀌면 채택하지 않는다.
- 최초 로딩·실패·불명확한 bind 모드에서는 쓰기 단추를 잠근다. 저장/적용/삭제/장착/해제/귀속 해제 직전 서버 기록을 다시 읽는다. 프리셋 내용, 모드, 해제 비용/잔액이 달라지면 실행을 취소하고 최신 내용을 보여 준다.
- 같은 기기의 다른 성장·모집·출격 요청과 잠금을 공유한다. 연속 클릭을 한 번만 처리한다. 요청 시작 시의 계정/상태 객체/기체 UID를 보존하며, 계정 변경 후 옛 응답이 UI나 sync rev에 들어오지 않는다.
- POST 응답이 모호하면 자동 재전송하지 않고 GET으로 확인한다. 창을 닫은 뒤 도착한 성공은 해당 계정에만 반영하고 창을 다시 열지 않는다. 저장/덮어쓰기/삭제 확인을 닫은 사전 GET은 POST를 보내지 않는다.
- 조회의 rev는 sync rev에 반영하지 않는다. 확정 POST의 rev가 있을 때만 전송 계층이 반영한다. 저장/삭제 응답에는 rev가 없는 현행 계약도 유지한다.
- 다중 기기의 GET→POST 사이 동시 변경까지 원자화하는 것은 서버 계약의 후속 범위다. 프론트의 사전 확인만으로 서버 동시성 보장을 주장하지 않는다.

## 이어받기

후속 기능 화면 4묶음(서킷·정제 → 목표/계보 → 조각/회수 → 귀속/프리셋)은 통합 브랜치에서 구현했다. 다음은 출시 전 검수/계약 마무리다.

1. CONTRACT의 미완료 상대 준비 API(`server/battle.js` find/next에 circuit 또는 확정 stats)와 숙련/목표 다중 기기 원자화 요청을 Claude와 조율한다. GPT는 임의 서버 덮어쓰기나 추정 수치를 만들지 않는다.
2. 신규 사용자 진입/실기기/성능·대규모 보관함·출시 전 전체 동선을 검수한다.
3. 귀속/계보 제한 활성화와 main 반영·운영 배포는 별도 사용자 지시를 받는다. 활성화 작업에는 handoff28의 migration024 확인·bindnow.sql·스위치·검사가 포함되며 이 UI 커밋에 섞지 않는다.

로컬 미리보기 재시작: `npm run build` 후 `node node_modules/wrangler/bin/wrangler.js dev --local --persist-to .wrangler/merged-ui-state --ip 127.0.0.1 --port 8841`. 운영 배포 명령을 사용하지 않는다. Worker가 열려 파일 잠금이 걸리면 이 로컬 검수 프로세스를 먼저 종료하고 빌드한다.
