# 랭킹·도감 화면 이관 · 2026-09-27

## 시안과 실제 계약

- `Downloads/rowar_ui_rebuild/ranking.png`의 기록 보관소 좌측 메뉴, 전장 배너, 상위 3인 강조, 순위표, 내 전적 패널을 사용했다. 모바일은 보관소 탭→배너→상위 3인→내 전적→목록 순서다. 별도 도감 시안은 없어서 랭킹과 같은 화면 계열의 보관소로 구성했다.
- 이 브랜치의 `GET /api/ranking`은 상위 최대 50명의 순위·닉네임·승패·칭호와 내 순위·승패, 집계 시각만 제공한다. 시안의 시즌/클랜/전투력/변동치/상대 기체 초상은 실제 데이터가 없어 표시하지 않았다. 순위는 서버 순서이며 승률은 받은 승패로 계산한다. 상위 3인은 큰 카드, 4위부터 한 쪽 10명의 표에 둔다. 첫 방문은 내 항목이 있는 쪽을 연다.
- 도감은 `js/codex.js`와 `GET/POST /api/codex`의 현재 규칙 그대로다. 몬스터 4단계, 기체·파츠 수집, 활성화 비용, 이정표 수령, 칭호 선택을 유지한다. 모으기 전 이름·조건·환급액·칭호 해금 정보의 기존 숨김 정책을 유지했다. 현재 활성화 수와 다음 이정표까지 남은 칸 수만 미리 표시한다.

## 검수

- `node tools/ui-preview.mjs 8812 --sample-archive`로 로컬 예시 계정 23인 목록·내 12위·다음 쪽·도감 세 종류를 확인했다. C급 몬스터 한 칸을 활성화하자 크레딧 400 차감, 활성화 1→2, 대기 18→17로 즉시 갱신됐다. 이 값들은 UI 검수용 가상 기록이다.
- PC와 1024px, 390px, 360px에서 배치와 가로 넘침을 확인했다. 모바일 390/360px에서 `documentElement.scrollWidth`는 문서 폭과 같았다. 브라우저 오류 로그가 없었다. 브라우저 도구로 시각 검수했으며 별도 이미지 파일은 저장하지 않았다.
- `tools/ranking-ui-check.mjs`, `tools/codexcheck.mjs`, `tools/battle-ui-check.mjs`, `tools/dispatch-ui-check.mjs` 통과. `node server/build.mjs`에 새 CSS와 JS가 포함되는 것을 확인했다.
- 운영 계정/API에서 재화를 소비한 검수는 하지 않았다. 실제 main 병합·운영 배포도 하지 않았다.
