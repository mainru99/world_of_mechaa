## 파일과 책임

- `js/ui/recruitment.js`: 순수 확률 파생 함수와 뽑기 화면/확률표/기체 목록 렌더러. `RECRUITMENT_CHANNELS`는 소개 문구·기본 기체만 정의한다. 추첨 규칙은 `PULL_CUR`에서 읽는다. 추후 분리 모집 도입 시 서버/공유 규칙 합의 후 이 표시 모듈을 확장할 수 있다.
- `themes/recruitment-v2.css`: 새 화면의 전용 배치, PC/태블릿/모바일 스타일, 기존 캡슐 위에 배너 전환. 기존 `style.css`의 캡슐 충전·개방·등급색 애니메이션을 재사용한다.
- `js/game.js`: 기존 `renderGacha`를 새 뷰에 연결, 소개 기체/확률표/목록 모달, 기존 상점·보관함 탭 스타일 연결, `doPull`의 연출과 요청 상태 관리.
- `index.html`: CSS와 캐시 버전 로드.
- `tools/recruitment-ui-check.mjs`: 확률 합산과 실제 `doPull` 추출 함수로 비동기 동작 검증.
- `tools/ui-preview.mjs`: 기본은 조회 전용. `--sample-pulls`를 명시한 경우에만 예시 계정 메모리에서 공유 `rollPull`을 이용해 샘플 보상을 생성한다. 운영 API/DB/네트워크 프록시가 없다. 프로세스 재시작 시 샘플 데이터 초기화.

## 확률과 연출 계약

1. 획득 종류는 풀 가중치 합계로 정규화한다. 기체 등급 확률은 `기체 등장 × 등급 비중`, 개별 기체는 해당 등급의 실제 기체 수로 나눈다. 파츠도 `파츠 등장 × 파츠 등급 비중`으로 표시한다. 기존 화면의 조건부 파츠 52/30/14/4%를 뽑기 1회 확률과 혼동하지 않도록 모두 1회 기준으로 통일했다. 반올림 안내 포함.
2. 배너/소개/도감/결과 기체는 모두 정지 PNG다. 큰 격납고 이그니스의 10프레임 규칙에 영향 없다. 새로운 이미지 생성/수정 없음. 사용 배경 `assets/backgrounds/gacha.webp`, 캡슐 `assets/gacha/core-capsule.png`, 재화 `assets/ui/coin-*.png`.
3. 대기 중에는 기체 배너다. 누르면 같은 공간에 캡슐이 나타나 충전 760ms→등급 회전 520ms→개방 700ms를 거친다. 모션 감소 시 기존 120/100/120ms를 사용한다. 보상은 서버 응답을 적용하며 `bestPrize`/`showReveal` 기존 선택 규칙 유지.
4. `_pullPending`으로 중복 호출 및 모집 창구/소개 기체/상점 탭 전환을 막는다. 뽑기 버튼은 진행 중 비활성화/aria-busy 표시. 주 메뉴 이동은 가능하다. 선택 통화·상태 객체·계정 ID는 요청 시작에 포착한다.
5. 뽑기가 서버에서 완료되면 다른 화면으로 이동했어도 같은 계정의 보상과 재화를 저장한다. 뽑기 화면에서만 결과 모달을 연다. 계정/상태 객체가 교체되었다면 이전 결과를 새 계정에 적용하지 않는다. finally에서 실패/예외 때도 캡슐과 진행 잠금을 해제한다.
6. 뽑기 API 및 비용·확률·보상·중복 전환은 변경하지 않았다. 향후 기체/파츠 모집 분리는 서버 규칙과 함께 별도 작업이다.
