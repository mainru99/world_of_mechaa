## 계보의 공개 기준

`js/ui/development-visibility.js`가 보유 목록·현재 선택 경로·저장된 목표를 입력받는다. 별도 연구 완료 필드가 없는 서버에서 새 저장값을 만들지 않는다. `relatedTypes`의 선행/후행/분화 경로와 `goalOk`의 선행 보유 조건을 사용한다.

- 보유 기체/현재 목표 공개. 다른 보유 기체를 눌러 경로를 바꿀 수 있다.
- 현재 경로에 있고 개발 목표 조건을 충족한 미보유 기체 공개. 아직 잠긴 기체, 경로 밖 미보유 기체는 `??`.
- 미공개 노드에는 이미지·이름·특징·스킬·클릭 동작이 없다. 목록·상세·접근성 이름·연결 title에도 같은 기준을 적용한다. 미공개 실명은 검색 대상에서 제외한다. 조각을 보유했다는 이유만으로 잠긴 기체가 공개되지는 않는다.
- 직접 선택 호출도 공개 판정을 통과해야 한다. 외부에서 미공개 ID로 창을 열면 현재 목표/보유 기체로 돌아간다.
- 계보 위치·등급·연결은 보존한다. 클라이언트 표시 정책이며 정적 기체 데이터에 대한 접근 제어를 의미하지 않는다. 뽑기 전체 도감이나 보유 조각 보관함까지 숨기는 변경은 아니다.

관련 파일: `development-graph.js`, `development-view.js`, `development-manager.js`, `themes/development-v2.css`. `development-manager.info()`는 합성/회수의 목표 비교용 메타데이터를 제공한다.

## 조각 합성

뽑기 → 기체 조각 보관함 → **조각 합성**. `js/ui/shard-view.js` 표시와 `shard-manager.js` 요청/상태 어댑터를 사용한다.

- C/UC/R/UQ 재료 등급 선택. 같은 등급의 여러 기체 조각을 6~10개 섞을 수 있다. 등급 변경 시 선택 재료를 비운다. EP 재료 창구는 없다.
- 재료별 보유 수량·정수 입력·증감 버튼·총 10개 상한. 입력 즉시 합계와 확률을 갱신한다. 잘못된 수량은 거절하고 이전 유효 선택을 유지한다.
- 공유 `synthCheck`/`synthRates`와 CONST의 수량 배율·스크랩 비용을 읽는다. 6개 성공 25%, 10개 53%, 명작 1%. UQ의 성공/명작은 모두 EP지만 수량이 다르므로 별도 행으로 설명한다.
- 결과 등급이 목표 등급과 같으면 그 목표 기체를 표시한다. 그 외 결과는 해당 등급 무작위로 안내하며 특정 기체를 보장하지 않는다.
- 목표 조각을 재료로 고르면 진행률 감소 가능성을 안내한다. 최종 재료와 스크랩을 확인하고 소비한다. 기체는 소비하지 않는다.
- POST `/api/shop {action:'synth',mats}`. `net.synthesize`는 기존 API를 감싸며 계정이 바뀐 응답은 rev와 상태에 반영하지 않는다.
- 서버 응답의 `items`, `credits`, `cores`, `scrap`, `synth`만 채택한다. 재료 차감/확률 추첨/보상 지급을 클라이언트에서 계산하지 않는다. 동급·성공·명작 결과 카드와 실제 used/spent를 표시한다. 완료 카드를 스크롤/포커스로 바로 보여 준다. 명작 연출은 reduced-motion을 존중한다.
- 실패/시간 초과는 state 재조회로 확인한다. 자동으로 같은 합성을 재전송하지 않는다. 결과 기록 조회 API가 없어 응답을 잃은 합성의 등급을 추측하지 않는다.

## 일일 회수

파견 → **회수 작전**, 또는 보관함 → **일일 회수**. 같은 기체의 복제본도 UID별로 선택할 수 있다.

- GET `/api/salvage`의 day/endsAt/daily/left/tiers/goal을 표시한다. 하루 2회, UTC 경계 = 한국 시간 09:00. 상태를 받기 전에는 임의의 잔여 횟수를 표시하지 않는다.
- 실제 지급 대상 `goal`은 C~R이다. 숙련 개발 목표가 UQ/EP이거나 fallback을 쓰면 **숙련 목표와 실제 회수 대상이 다름**을 명시한다.
- 난이도 정찰/회수/강습: 몬스터 내구·공격 ×0.7/1.0/1.3, 승리 조각 1/2/3. 다른 UID를 고르면 GET으로 받은 day와 공유 `salvFoe(day,tier,level)`로 같은 레벨의 상대를 미리 표시한다. GET API에 없는 UID 파라미터를 만들지 않는다.
- 출격 확인에는 승리 보상과 승패 무관 1회 소비를 표시한다. 추가 경험치/크레딧/피로도 보상은 없다.
- POST 직전 GET으로 날짜·실제 보상 대상·잔여 횟수를 재확인한다. 바뀌었거나 읽지 못하면 출격을 보내지 않고 다시 준비하도록 한다. 이후 POST `{tier,uid}`의 서버 판정이 최종 기준이다.
- POST 응답에는 items/rev가 없다. 승패/got/left/goal은 확정 결과로 표시하고, 보관함은 GET `/api/state`의 items로 확인한다. POST goal.have를 inventory에 복사하거나 로컬에서 got를 더하지 않는다.
- 서버 stats/foe/seed와 공유 `runSalvage`로 사건을 재생한다. 클라이언트 재생 승패와 서버 승패가 다른 경우 서버 결과만 표시한다. 기존 arena의 배속·건너뛰기와 정지 에셋을 사용한다. EXP/전적/전투 피로를 일반 대전 정산 함수에 넣지 않는다.
- 결과에는 실제 지급 대상·조각 수·목표 진행·잔여 횟수와 원래 파견/보관함으로 돌아가는 동작을 제공한다. 보관함 재조회를 실패하면 작전은 기록됐음을 알리고 재조회 안내를 표시한다.

## 요청·계정·이동 격리

- manager는 state 객체와 account ID를 캡처한다. 읽기/쓰기 중복 잠금, 반대쪽 서킷/개발 목표/뽑기/상점/파견/도전 잠금을 연결했다.
- 읽기는 items/재화/robots의 스냅샷이 그대로일 때만 채택한다. 회수 조회는 items/mastery 메타데이터만, 합성 초기/실패 조회는 items와 관련 지갑 값도 확인한다. 편성/장비/기체 레벨/경험치/전적을 되감지 않는다.
- state 부분 조회는 sync rev를 임의로 올리지 않는 기존 `growthState` 계약을 유지한다. synth POST의 rev는 기존 통신 계약대로 기록한다.
- 창을 닫은 뒤 같은 계정에서 POST가 끝나면 데이터를 채택하고 알림만 표시한다. 닫힌 창을 다시 열거나 전투로 끌고 가지 않는다. 계정/state가 바뀐 응답은 폐기한다.
- 회수 재생 후 결과 교체는 account/state와 battle request epoch를 확인한다. 다른 화면/새 전투로 떠났으면 이전 결과를 붙이지 않는다.
- 공통 게임 설명의 개발·보급 항목에도 공개 기준/합성/회수를 연결했다. 서버/판정/확률 설정은 새로 만들지 않았다.
