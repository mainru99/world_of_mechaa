# 보급 상점·기체 조각 보관함 이관 · 2026-09-27

## 적용 범위

- 별도 상점 시안은 없으므로 `gatcha.png`의 어두운 산업 배경·붉은 선택 상태와 기존 개편 화면의 패널 규칙을 이어받았다. 실제 기체 PNG와 기존 파츠 아이콘을 사용했다.
- 상점은 이번 진열 6칸, 남은 시간, 레벨 기준 가격, 구매 가능 수, 종류별 실제 등장 비율, 유료 갱신 비용·횟수를 보여 준다. 구매한 칸과 재화 부족 버튼을 구분한다.
- 보관함은 기체별 조각 수와 조립 기준, 진행 막대, 보유 기체의 중복 조립 보상을 보여 준다. 빈 목록에서도 상점으로 갈 수 있다.
- 진열·가격·상품 서명·조립 결과는 기존 `/api/shop`과 `js/shop.js`의 서버 판정을 그대로 따른다. 화면용 가짜 상품이나 새 규칙은 없다.

## 동작 및 경계

- 상점 응답은 현재 계정·상태 객체·화면·요청 순번과 일치할 때만 적용한다. 계정 전환 또는 탭 이동 뒤 늦게 온 조회 응답은 화면을 덮지 않는다.
- 구매·갱신·조립 요청 중에는 해당 행동 버튼을 잠가 중복 요청을 막는다. 요청 중 다른 보급 탭으로 이동했다면 응답 뒤 현재 탭을 새 데이터로 다시 그린다.
- 진열 불일치 `409`는 최신 진열을 다시 가져오게 한다. 조회 실패와 오프라인 상태에는 재시도 또는 연결 안내를 표시한다.
- 조립은 기존 서버 규칙대로 새 기체를 격납고에 추가하거나, 이미 가진 기체라면 등급별 자원으로 전환한다.

## 검수

- `node tools/ui-preview.mjs 8815 --sample-shop`의 메모리 전용 예시 계정으로 기체 조각 구매 → 보유 수량/판매 완료/지갑 반영, 유료 갱신 → 새 상품/비용 증가, 보유 기체 조립 → 조각 차감/중복 보상을 확인했다. 실제 계정·운영 DB는 사용하지 않았다.
- IAB에서 PC 기본 폭, 1024px, 390px, 360px 배치를 확인했다. 360px/390px/1024px 문서 가로 넘침은 없었다. 360px 상품은 2열을 유지한다.
- `node tools/shopcheck.mjs`, `tools/recruitment-ui-check.mjs`, `tools/hangar-ui-check.mjs`, `tools/login-ui-check.mjs`, `node --check` 2건, `node server/build.mjs` 통과.

## 남은 작업

- 주간 시련·공동 레이드와 전선의 본문/결과/공통 모달을 같은 화면 언어로 정리한다.
- 전체 UI 완성 뒤 스테이징 계정·실제 API·main 신규 동작을 별도로 통합 검수한다. 이 단계에서는 `codex/ui-rebuild`만 커밋·푸시하며 main 병합과 운영 배포를 하지 않는다.
