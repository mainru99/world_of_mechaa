# 밸런스 검증 도구

전부 **읽기 전용**이다. `data/balance.js` 를 고친 뒤 돌려서 무엇이 무너졌는지 본다.
수치를 만드는 스크립트가 아니라 재는 스크립트다 — 결과가 마음에 안 들면 데이터를 직접 고친다.

```bash
node tools/verify.mjs    # 종합. 이것 하나면 대부분 보인다
node tools/intra.mjs     # 같은 등급 안에서 기체들이 서로 대등한가
node tools/mon.mjs       # 몬스터가 같은 등급 기체를 상대로 반반인가
node tools/match.mjs     # 게임이 실제로 붙여 주는 상대와의 승률 (새 플레이어 경험)
node tools/gap.mjs       # 등급 하나가 레벨 몇 개 값인가 → CONST.TIER_LV 의 근거
node tools/sens.mjs      # 레벨·공격력 차이가 승률을 얼마나 움직이나
node tools/mirror.mjs    # 완전히 같은 기체끼리 붙였을 때 50% 인가 (선공 편향 감시)

node tools/parts.mjs     # 파츠 한 세트가 승률·전투력을 얼마나 올리나
node tools/parts2.mjs    # 파츠를 낀 상태의 등급 사다리 · 파츠가 등급을 뒤집나
node tools/partlv.mjs    # 파츠 세트 = 레벨 몇 개 → CONST.PART_LV 의 근거
node tools/match2.mjs    # 파츠를 낀 상태에서 생성 상대와의 승률
```

`match.mjs` 는 맨몸, `match2.mjs` 는 파츠를 낀 상태다. **둘 다 봐야 한다** —
처음에 맨몸으로만 재는 바람에 "파츠를 낄 수 없는 상대(몬스터)가 공짜 승리가 된다"를
놓칠 뻔했다.

## 읽는 법 — 건강한 값

| 도구 | 봐야 할 곳 | 건강한 범위 |
|---|---|---|
| `verify` ③ | 거울 대결 | **50% ± 2** — 벗어나면 시뮬에 편향이 생긴 것이다 |
| `verify` ④ | 등급 사다리 대각선 | **50% 근처** |
| `verify` ⑤ | 커먼이 따라잡는 레벨 | UC +3 / R +6 / UQ +7 / **EP +15** |
| `intra` | 등급별 승률 폭 | **35~65%** — 한쪽이 20% 밑이면 그 기체는 죽은 것이다 |
| `mon` | 등급별 기체 승률 | **45~55%** |
| `match` | 커먼 보유자 행 | **40~50%** — 새 플레이어가 계속 지면 안 된다 |
| `match2` | 커먼 보유 Lv.15 열 | **40~55%** — 장비를 갖춰도 여기가 흔들리면 안 된다 |
| `parts2` ③ | 파츠 낀 사다리 | 맨몸 사다리와 **비슷하면** 정상 (조금 완만한 건 정상) |

## 함정 두 가지

1. **시드를 고정 집합으로 쓰지 말 것.** 기체마다 같은 난수열을 돌리면 표본이 상관돼
   없는 편향이 보인다. 실제로 거울 대결이 50.4% 인데 54.5% 로 읽힌 적이 있다.
   여기 도구들은 전부 매번 새 시드를 쓴다.
2. **승률은 세기의 가파른 함수다.** 스탯 5% 차이가 승률 20%p 를 움직인다.
   수치를 반복 보정할 때 이득값을 크게 잡으면 수렴하지 않고 진동한다(실측: 0.55 발산, 0.10 수렴).
